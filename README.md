# Portfolio OS

An interactive, terminal-first developer portfolio that boots like an operating system, syncs your projects live from GitHub, and never needs its components edited again — just edit `js/config.js`.

**Zero build step.** It's plain HTML/CSS/JS, so you can open `index.html` directly, drag the folder onto Netlify/Vercel, or drop it into any static host.

---

## 1. Quick start

1. Open `js/config.js` and set:
   ```js
   githubUsername: "your-github-username",
   ```
   Everything in **Projects**, **GitHub**, **Open Source**, and the terminal's `projects` / `github` / `stats` commands pulls live from this account via the public GitHub REST API — no token, no manual project entries.
2. Fill in the rest of `js/config.js` — bio, socials, skills, experience, education, certifications, achievements, blog posts. That one file drives the entire site.
3. Drop your real résumé PDF at `assets/resume.pdf` (referenced by `CONFIG.resumeUrl`).
4. **Make the contact form actually send:** sign up free at [formspree.io](https://formspree.io), create a form, and paste the endpoint into `contactFormEndpoint` in `js/config.js`. Until you do, the form still renders and validates but only shows a "preview only" message on submit — nothing is lost, it just isn't wired to a mailbox yet.
5. **Replace the placeholder domain**: search the project for `yourdomain.com` (it appears in `index.html`'s canonical/OG tags, `robots.txt`, and `sitemap.xml`) and swap in your real deployed URL.
6. Open `index.html` in a browser, or deploy the folder as-is to Vercel/Netlify/GitHub Pages.

## 2. What's included

- **Boot sequence** — "Initializing Portfolio OS…" loader with progress bar, into the desktop.
- **Full OS shell** — top bar (traffic-light dots, live clock, sync indicator), sidebar navigation, status bar.
- **Interactive terminal** on Home with:
  - Real command parser, command history (↑/↓), Tab autocompletion
  - A virtual filesystem (`ls`, `cd`, `pwd`, `cat`, `tree`, `find`, `grep`)
  - Content commands: `about`, `whoami`, `projects`, `skills`, `experience`, `education`, `certifications`, `achievements`, `opensource`, `resume`, `contact`, `social`, `github`, `github activity`, `blog`
  - System commands: `neofetch`, `stats`, `date`, `time`, `weather`, `theme <name>`, `history`
  - Fun: `matrix`, `ascii`, `snake`, `typingtest`, `sudo hire me`, `sudo coffee`, Konami code → Matrix rain overlay (↑↑↓↓←→←→ b a)
- **Live GitHub integration** — repos, stars, forks, languages, avatar, bio, followers, contribution heatmap. Filterable/searchable/sortable project grid, generated with **zero manual entry**.
- **Sections as windows**: About, Projects, Skills (animated bars), Experience/Education (timeline), Certifications, Achievements, Open Source, GitHub dashboard, Blog, Resume (preview + download + print), Contact (copy buttons + working form UI), Settings.
- **7 themes**: hacker (default), ubuntu, powershell, vscode, dracula, matrix, light — switchable via Settings, swatches, or `theme <name>`.
- **Effects**: CRT scanlines, vignette, film grain, floating particles, neon glow borders — all toggleable in Settings, and disabled automatically under `prefers-reduced-motion`.
- **Command palette** (Ctrl/Cmd+K) — jump to any section or run a command.
- **Fake "breach" simulation** — run `hack` in the terminal for a theatrical, obviously-fictional "you're being hacked" sequence: glitchy red terminal logs (fake IP, fake firewall bypass, a "webcam access: denied" joke), a screen-shake + flashing glitch title, then a clear reveal screen confirming nothing actually happened. Press ESC or click anywhere to exit at any point. No real system access, no data collection — it's pure CSS/JS theater for fun.
- **Two playable mini-games**: Snake and a Typing Speed Test (WPM + accuracy).
- **System Monitor** — a live-animated window (and `sysmon`/`htop`/`top` command) with glowing CPU/RAM/Disk graphs, network up/down bars, uptime, and a rotating fake process list. Clearly simulated telemetry (a browser can't read real system stats) — it's atmosphere, not a real dashboard, and pauses its animation loop when you're not on that window so it doesn't burn CPU in the background.
- **Hacker utility commands**: `passwordgen`, `uuid`, `hash [sha1|sha256|sha512] <text>`, `json <text>` (validate/pretty-print), `color #hex`, `regex /pattern/flags text`, `shortcuts`.
- **Chain-swing avatar illustration** — a small stylized figure sitting on a swing suspended by two chains, glowing in the site's neon palette, with a gentle idle sway (respects `prefers-reduced-motion`). Appears as the About-window hero and a mini version in the sidebar. It's pure SVG (not a photo), generated by `swingAvatarSVG()` in `js/app.js` — restyle it, or swap it for a real photo, by editing that one function.
- **Favicon + Open Graph image** — `assets/favicon.svg` (+ PNG fallbacks for older browsers and manifest icons) and `assets/og-image.png` (1200×630 share preview), wired into `index.html`'s `<head>` and `manifest.json`.
- **SEO files** — `robots.txt` and `sitemap.xml` at the project root. Since this is a single-page app, the sitemap lists one URL; see the comment inside it if you later add real routes.
- **Working contact form** — posts to Formspree via `fetch`, with real loading/success/error states (see step 4 above to activate it).
- **404 page & lightweight offline support** — `404.html` (served automatically by most static hosts for unmatched routes) and `offline.html` + `service-worker.js`, which cache the app shell so repeat visits load instantly and show a themed offline page if the network drops with nothing cached. This is intentionally minimal (see the PWA row in the scope table below for the full version).
- **Config-driven content** — `js/config.js` is the single source of truth described in the brief; no React/DOM code needs touching for content updates.
- **Responsive** down to mobile (collapsible sidebar, single-column grids), keyboard-accessible, respects reduced motion.

## 3. Honest scope note

The original brief describes a multi-week, full production system (Next.js SSR + GraphQL, PWA offline caching, a password-protected admin analytics dashboard, Three.js scenes, voice recognition, and a full arcade of Tetris/2048/Minesweeper). Building all of that to a genuinely polished standard isn't realistic in one pass, so this delivers a **complete, working core** — everything above — with a clean, modular codebase you (or an AI pair-programmer) can extend. Below is what's deliberately left as a roadmap rather than half-built:

| Not included | Why / how to add it |
|---|---|
| Next.js/React rewrite | Current version is framework-free by design (no build step, deploy anywhere). Porting to Next.js App Router is straightforward: each `render*()` function in `js/app.js` maps 1:1 to a route/component. |
| GitHub GraphQL (pinned repos, contribution calendar data) | GraphQL requires an auth token, which can't safely live in client-side code. Add a small serverless function (Vercel Edge Function) that holds the token server-side and proxies GraphQL queries. |
| Full PWA offline caching | A lightweight version now ships (`service-worker.js` caches the app shell + serves `offline.html`). Not included: runtime caching of live GitHub API responses, background sync, and update-available prompts — add a library like Workbox if you want the complete experience. |
| Admin analytics dashboard with auth | Needs a real backend (DB + auth). Recommend Supabase/Postgres + a protected `/admin` route once you add a backend. |
| Full game arcade (Tetris, 2048, Minesweeper) | Snake and a typing test are included as fully playable proof points; the same `render*()` + canvas pattern extends cleanly to more games. |
| Voice commands / speech synthesis | Browser `SpeechRecognition`/`SpeechSynthesis` APIs can be wired into `Terminal.run()` in an afternoon — left out to keep the core rock-solid rather than adding untested surface area. |
| Live weather | Needs a weather API key (e.g. OpenWeather); the `weather` command is stubbed with a note where to plug it in. |
| Blog comments, MDX rendering | Blog currently reads from `config.js`; swap in an MDX pipeline (e.g. `next-mdx-remote`) if/when you move to Next.js. |

## 4. File structure

```
portfolio-os/
├── index.html          # shell markup
├── 404.html              # custom not-found page (static hosts serve this automatically)
├── offline.html           # shown by the service worker when offline with nothing cached
├── service-worker.js       # minimal app-shell caching (see feature list above)
├── manifest.json            # PWA manifest (installable, lightweight offline via service-worker.js)
├── robots.txt                # crawl rules
├── sitemap.xml                 # single-URL sitemap (SPA — see comment inside)
├── css/
│   └── style.css        # all styling, themes, effects, responsive rules
├── js/
│   ├── config.js         # <-- EDIT THIS for all your content
│   ├── github.js          # GitHub REST API integration
│   ├── effects.js         # particles, matrix rain, konami code
│   ├── terminal.js        # command parser + virtual filesystem
│   └── app.js              # boot sequence, window manager, section renderers
└── assets/               # resume.pdf, favicon/OG images (already generated)
```

## 5. Notes on the GitHub API

- Uses the **public REST API**, unauthenticated: 60 requests/hour per visitor IP. Fine for a personal site; if you get heavy traffic, add a token via a serverless proxy (never ship a token in client JS).
- The contribution heatmap uses the free `ghchart.rshah.org` image service (no key needed). Swap for a self-hosted GraphQL-based version if you want exact private/public contribution breakdowns.

## 6. Customizing look & feel

All colors, glows, and effect intensity are CSS custom properties at the top of `css/style.css` (`:root`) and per-theme overrides just below. Change `--primary`/`--secondary`/`--accent` to retheme everything in one place.
